# Tradeoffs Lab

**Production AI, built both ways.**

Every study in this repository ships two things: the approach that was chosen, and the strongest approach that was rejected — both as running code, under the same input and output contract. Alongside them sits the rule that decides between them.

Most engineering portfolios show one path through one problem. That proves the path works. It doesn't show the judgement that picked it. These studies are built to show the judgement.

**Companion repositories:** [rag-lab](https://github.com/akhil1299/rag-lab) — retrieval, measured phase by phase. [agent-lab](https://github.com/akhil1299/agent-lab) — a point-in-time AI data platform and agent over SEC filings.

## How each study is built

Three files carry the method. They are the point of the repository.

**`README.md`** — what the study does, what works, what didn't work and why, and the numbers. Failures are documented with their root cause, not omitted.

**`DECISIONS.md`** — every design decision with three parts: what was chosen, what was rejected, and the **switch condition** — the circumstance under which the rejected option becomes the right one. A decision without a switch condition is an opinion; with one, it's engineering.

**`forks.py`** — the rejected alternatives as executable code, taking the same input and returning the same output as the chosen path. Only the internals differ. Reading it alongside `DECISIONS.md` shows the option space, not just the choice.

## Why this structure

Three questions come up in every serious technical conversation about a system:

- *Why did you build it this way?* — answered by `DECISIONS.md`
- *What else could you have done?* — answered by `forks.py`
- *When would you choose differently?* — answered by the switch conditions

Writing the answers while the reasoning is fresh produces better engineering than reconstructing them later, and it leaves a repository that can be read by someone who wasn't there.

## Standards

- **Reproducible from source.** Datasets are generated by seeded scripts committed to the repository, so every number can be rebuilt rather than taken on trust.
- **Measured, not asserted.** Latency, token counts and cost are instrumented at the call site. Claims in a README trace to something that was run.
- **Honest about limits.** Each study states what it does not do and what its approach cannot catch.
- **Finished to a standard, not to a deadline.** Studies are small on purpose so they can be complete.
